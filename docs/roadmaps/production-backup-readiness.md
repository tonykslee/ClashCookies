## November 15 M5/M6 recovery evidence and outstanding questions

- **Authorization/execution:** The operator explicitly authorized one manual production backup/encryption/B2 upload. Original isolated runner at `15677f03` ran once and returned systemd failure (exit 1), without a diagnostic failure stage. An encrypted **daily** object nonetheless appeared at `clashcookies-prod/daily/2026/11/15/clashcookies-prod-20261115T102211857Z-094fb4381c31.dump.age`. Its independent B2 HEAD/retention checks confirmed 29,654,406 bytes, SHA-256 `6aaccd60419234a50761ffb80223d06bc8f7f9922a2a1abb5ae7ff5a4404686b`, SSE AES256, Governance lock through `2026-11-29T11:22:31+00:00`. No weekly object was observed on Sunday. Do not infer why the original command failed or assert that all retention classes are functional.
- **Corrective code:** PR [#2001](https://github.com/tonykslee/ClashCookies/pull/2001) addressed Object Lock whole-second retention rounding and introduced allowlisted failure stages/exit diagnostics without logging raw stderr/secrets; merged to `dev` at `eb955ca5`. The original production runner has **not** been updated; no corrected production rerun or weekly retention check is claimed.
- **Independent restore:** On a separate Windows machine, AWS CLI with the distinct read-only B2 recovery profile retrieved the same encrypted daily object. Locally computed SHA-256 **exactly matched** its metadata. Age 1.3.2 with the primary off-host identity decrypted it without error. PostgreSQL 17.12 `pg_restore --list` passed, and `pg_restore --no-owner --no-acl --exit-on-error --single-transaction` succeeded into a disposable UTF-8 / C-locale PostgreSQL 17.12 database, on localhost port 55432 in an isolated data directory. Validation showed 119 `public` tables; 109 tables with nonzero `pg_stat_user_tables.n_live_tup` and approximately 452,298 **estimated**, not exact, rows. A running application was not tested. The isolated server was shut down and operator-confirmed cleanup removed the plaintext dump, cluster and restore logs; encrypted file retained locally.
- **Evidence classification:** Results are operator-shared terminal output, not a GitHub CI run or an independent host/provider audit. The full transaction succeeded but does not establish every application-level invariant or an unattended backup cycle.
- **Still open:** durable off-host administrative B2 key escrow; independent primary/emergency identity custody review; backup success-path notification and independent expected-object monitoring; root cause and safe revalidation of weekly upload failure; deploying the fix to the isolated runner (separate permission); scheduled timer activation (separate explicit authorization); release/staging/migration recovery gates. **Do not automatically run another backup, start the timer, deploy, or promote `dev` to `main`.**
